unchanged Java 1.21.11 v5 physical runtime. It is adopted in **isolated catalogs**,
including through public MCP with service restarts. No user's catalog, live
world or historical unrestricted proposal is modified by this audit.

Follow-up: the [live construction audit](reference-door-live-construction.md)
first found a command-placement gap at stage 38, then verified the repaired v6
entry and explicit observer initialization. Fresh public adoption, all 43 build
steps, two ordinary cycles, restart and all 43 removal steps passed. The results
below retain their original v5 model-audit meaning; old execution pins are not
reinterpreted as v6 permission.

## Regression boundaries

New tests cover schema downgrade rejection; duplicate/invalid observation names;
normal completion versus interrupted failure; state carried across repeated use;
transient matching snapshots; wrong recurrent regions; intermediate pulses;
every phase of an unrelated running clock; budget exhaustion; malformed aperture
geometry and predicates; control polarity; relocation; retained child failure;
archive restart; public adoption; and existing target-placement gates.

Three older observation assertions sampled an earlier boundary than their intent:
after moving-block creation or `RetractBody`, before carrier registration. They
now explicitly distinguish staged occupancy without an entity from the later
registered carrier. No physical transition was changed to satisfy those tests.

Live conformance remains bounded by the retained measured histories. The new
graph proof is a model guarantee, not an exhaustive Minecraft proof. Future live
construction must use ordinary placement callbacks and confirm each expected
state; strict saved-state initialization cannot substitute for that trial.

The JSON example commands referenced historically in this document are retired.
Current explicit test-only export/replay instructions are in
[development-fixture-adapters.md](development-fixture-adapters.md).
Retained evidence and hashes describe their original execution and are unchanged.
