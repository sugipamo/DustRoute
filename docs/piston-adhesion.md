# スライム・ハチミツの粘着移動

状態: 下記の範囲で実装・検証完了（2026-09-28）。基点は develop `ad24b78`、ブランチは
`codex/piston-adhesion`。Java 1.21.11 / Yarn build.6 を基準とする。

## 到達点と順序

1. Rust の検査済み物理定義にスライム・ハチミツを登録する。
   支持面・導電性と粘着属性を独立に定義し、両者の非接着を表す。
2. 直線専用の収集を共通の押出し・引戻し収集へ置き換える。
   後方連結、側面分岐、枝の合流、12 ブロック上限、動かせない隣接物と
   移動先の障害物を区別する。移動順と残る移動元の除去・通知順も扱う。
3. 既存の MotionPlan、予約イベント、支持喪失、checkpoint / 探索状態復元へ
   接続する。旧検証結果の流用を防ぐため実行・物理コンテキストを更新する。
4. 6 方向、押出し・引戻し、上限、枝の合流、支持喪失、短い入力を回帰検証する。
   隔離実機で入力適用時刻と書込み・通知・最終状態を比較し、既存の実機記録も再生する。
5. snapshot 入出力、既存 Assembly の検証・配置経路との接続を確認し、
   対応範囲と実機証拠を記録する。

対象は現在扱えるブロックとスライム・ハチミツのブロック間移動。
エンティティの運搬・跳ね返り・滑り、アイテム、流体、インベントリ、
移動先にある部品の直接破壊、未対応部品の可動化は追加しない。
未対応の作用が必要な入力は成功扱いせず拒否する。
未観測領域を空気と見なさず、過去の checkpoint や子の要求を自動変換しない。

宣言外の機能・設計変更を先に実装すべきと判断した場合は、着手前に停止して
必要性と具体案をユーザーへ報告する。
Cargo は offline / locked、1 job、Rust テストは 1 thread。

## 初期調査

ローカルの対象版 JAR の `PistonHandler`、`PistonBlock`、`HoneyBlock`、
`SlimeBlock`、`Blocks`、`AbstractBlock` を `javap -p -c` で確認した。

- 粘着判定はブロック対の関係。スライムとハチミツ同士は接着しない。
- 後方の連結を先に収集し、側面は Java Direction の順序で探索する。
  既存の枝に合流すると収集順を組み替える。単純な座標ソートにはできない。
- 横にある不動ブロックは連結しないが、移動先の不動ブロックは移動を止める。
- 移動先を書いた後、上書きされずに残った移動元を除去する。
  その除去・形状通知は Java の座標 HashMap の列挙順に依存する。
- 引戻しも同じ収集器を使う。引戻せない場合でもピストン本体は戻る。

この静的調査だけでは実機一致を主張しない。

## 実装

物理定義に `Adhesion` と `PistonReaction` を追加した。スライムは全支持面と
導電性を持ち、ハチミツは衝突形状に由来する底面中央だけの支持と非導電性を持つ。
無効な材質・形状の組合せは Rust 定数の評価時に拒否する。
破壊される部品の側面接触は非接着として扱い、移動先での直接破壊は未対応として拒否する。

共通収集器を押出し・引戻しの両方から使い、既存 `MotionPlan` に移動先の書込み、
残存する移動元の除去、形状通知、通常通知を順に積む。
横の黒曜石は連結せず、移動先の黒曜石は移動を止める。
構造全体を引けない場合でも本体とヘッドは収納される。

実行・探索コンテキストは v17、物理定義 v8、配置検証 v5。
既存の device program v7 と同期 runtime v5 を共有する。
旧モデルへの受入れ拡大を防ぐため、材質名に基づく実行受入れ照合も行う。
不正な追加プロパティを持つ粘着ブロックでも旧モデルへの抜け道にはならない。

## 動かない試験の復元検証

`adhesion-blocked-20260928-a` は実機の観測と後片付けを完了したが、比較用 example が
移動途中の checkpoint を必須にしていたため `model_rejected` になった。
この結果を合格へ書き換えない。

比較入力に `restoration_scope=input_notifications` を明示した負例だけ、
実際に変わった入力の通知途中と入力境界からの復元を検証する。
このモードでは移動 carrier が一度でも現れたら拒否する。
既定の `movement_or_device` は従来の移動・内部状態を持つ復元条件を維持する。
測定した時刻、世界状態、書込み・通知の比較条件は緩和しない。

  宣言した比較範囲で一致し、途中状態の復元も通った。
- 新しい11件は圧縮した独立の実機記録として保存した。以前の43件と合わせた54件を
  最終モデルで再生した。初期5ケースの取得時と最終比較器の差も hash で区別する。
- 公開MCPで混在Assemblyの新しい親・子・状態Revisionを提案し、v17で再検証・採用した。
  r90配置16手順・撤去16手順を、各操作33回のサーバー確認読戻しで検証した。
  読戻し範囲は4,785セル。採用後・配置後・撤去後の3回のプロセス再起動を通した。
  未プレビュー、未観測chunk、外部変更、プレビュー後の変更、ON状態からの撤去を拒否した。
  ONでスライムと側面の石が上昇し、OFFで戻ること、隣のハチミツが残ることを
  サーバーの書込み記録でも確認した。撤去後の空領域と強制ロード解除を確認した。
  [公開API・保存記録・操作証拠](evidence/piston-adhesion-public-20260928.json.gz)を保持する。

比較対象はtick終端のブロック状態、順序付きpalette書込み、部品のtick配送、
有効部品への通常通知、ピストンイベントとcarrier境界。
内部レジスタ・履歴、全形状通知、不活性な通知先までは実機と比較していない。
公開配置も既存の権限・観測範囲・非原子操作という条件を維持する。

## 残る境界

後続の[固定コース飛行試験](flying-machine-short-course.md)では、既存runtimeの組合せで
6ブロック機体の10ブロック自走・停止を実機比較した。公開配置の対応範囲は拡大していない。

Java の source HashMap が同じ bucket に9個以上のキーを入れて衝突による
再配置を起こす場合は、列挙順を推測せず拒否する。通常の12個以下の収集順を
無条件な全座標保証へ拡大しない。全移動元・移動先と必要な通知領域の観測が必要。
プレイヤー等の運搬、スライムの跳ね返り、ハチミツの滑り、アイテムの生成、
粘着構造の万能な操作完了センサーは含まない。
