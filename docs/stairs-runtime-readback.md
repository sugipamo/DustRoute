# 階段の物理挙動と共通サーバー読戻し

状態: **宣言範囲の実装・実機比較・公開操作・最終回帰を完了**（2026-09-28）。
ブランチは `codex/data-driven-block-runtime`、変更前は `95eec33`。
最初の実機試験で読戻しの不足を報告して停止した後、共通化の承認を受けて再開した。
既存の v15 の検証結果は [passive-shapes-runtime.md](passive-shapes-runtime.md) を参照。

## 今回の対象と実装した範囲

- 石、丸石、クォーツ、滑らかなクォーツの階段。
- 上下、水平4方向、直線・内角左右・外角左右。`waterlogged=false` の完全な状態のみ。
- Rust 定数レジストリへの登録と、面ごとの支持・非導電性・ダストの段差接続。
- 水平隣接更新による形状再計算、形状変化で支持を失う部品の除去。
- ピストン移動完了時の到着先形状再計算と、既存の通知キュー・復元経路への接続。

形状と隣接判定は、ローカルにある Java 1.21.11 / Yarn build.6 の
`StairsBlock`、`PistonBlockEntity`、`SideShapeType` 等の実装を参照した。
未対応の階段材質、水没状態、板ガラス、流体・アイテム・エンティティは追加していない。
実行・探索コンテキストは v16、物理定義は v7、配置検証は v4。
旧コンテキストの合格を流用せず、明示した初期条件から再検証する。過去データの変換は行わない。

対象を絞った Rust テストは **16 件成功**。階段の 160 状態の支持面・回転、
内外角の優先順位、形状変化後の支持喪失、通知途中の checkpoint 復元、
移動先形状、配置検証と電気処理の段差判定を含む。
`cargo check -p dustroute-translate` と比較用 example のビルドも成功した。
Cargo は offline/locked・1 job、テストは 1 thread で実施した。
最終的な回帰・公開操作の検証結果は後述する。

## 最初の実機試験で見つかったこと

隔離した Java 1.21.11 ワールドで、内角を作る隣接階段をピストンで動かす試験を行った。
実際の入力パケットは game tick 148131 / 148147 に届いている。
サーバーの連続記録から導出した比較区間は tick 148131–148187。

位置 `(120002,180,999)` のクォーツ階段について、次の差が残った。

| 観測 | 状態 |
| --- | --- |
| クライアント初期状態 | `facing=north,half=top,shape=inner_left,waterlogged=false` |
| サーバーの書込み（tick 148132、sequence 2270） | `inner_left` → `straight` |
| クライアント最終状態 | `inner_left` のまま |
| サーバーの後片付け時（tick 148227、sequence 3628） | `straight` → Air |

比較範囲の他のセルは一致した。形状変更のサーバー書込みは flags **324**。
対象版の定数では `256 + 64 + 4` で、`NOTIFY_LISTENERS=2` を含まない。
これはクライアント側に古い形状が残ることと整合する。
後片付けの直前にもサーバー側は `straight` であり、後続処理で内角へ戻った記録ではない。
個々のパケット送信条件までを網羅した証明はしていない。

この原本は **`observation_incomplete`** として拒否されたまま保持する。
シミュレータとの比較に到達していないため、物理モデルの一致・不一致は未判定。
クライアントの状態をサーバートレースやモデル出力で上書きして合格にする変更は行っていない。
試験領域の撤去、所有する force-load の解除、サーバーの正常終了は完了した。

原本ハッシュ、該当書込み、比較区間、検証結果は
[監査記録](evidence/stairs-readback-20260928.json) に保存した。
[診断用の圧縮記録](evidence/stairs-readback-20260928.diagnostic.json.gz) は
原本の全 raw 記録、試験定義、初期・最終クライアント状態などを含む。
この記録から既存の `compare_device_circuits.observe` の同じ拒否を再現できる。
合格済み device fixture には追加していない。
原本は bounded capture で、比較区間外には破棄・抑制がある。宣言した比較区間は連続している。

## 階段固有の比較器変更だけでは済ませない理由

試験用 `mineflayer/e2e/piston-mixed-live.js` の snapshot と、公開ブリッジ
`mineflayer/bridge.js` の `scanRegion` は、ともに `bot.blockAt` と
`getProperties` によるクライアント状態を使う。待機や同じ scan の再実行だけでは、
通知されない状態変化を取得できる保証がない。

公開 MCP の誤判定そのものを今回の試験で再現したわけではないが、
同じ情報源を使う配置検証・診断にも影響し得る。
階段の最初の実機比較を進めるには、サーバー状態を独立に確認する観測経路が必要になる。

`observe_periodic_clock.py` と `observe_torch_burnout.py` には、
サーバーコンソールと `execute if block` を使った個別の状態確認処理がある。
ただし、静止・tick 制御した専用試験向けであり、公開ブリッジと共有する
任意領域の読戻し API にはなっていない。これらをそのまま通常の scan と同等には扱えない。

## 承認後に実装した共通読戻し

`mineflayer/readback.js` を隔離試験と公開 bridge の `scan_region` / `get_block` が共有する。
クライアント観測を候補にして、全セル・全プロパティ・空気・ロード状態を
Java 1.21.11 のコマンドで確認する。各条件確認自身が返す game tick を記録し、
全条件が同じ tick で成立した場合のみサーバー確認済みとして返す。
不一致の階段形状は5候補を独立に調べ、領域全体を再確認する。
モデルの予測値やサーバーの書込みトレースから欠測を補わない。

fresh request ID と nonce を照合し、未応答・権限不足・未ロード・繰返しの tick 跨ぎは拒否する。
Assembly の保存記録には配置前と各手順前後の証拠を保持する。再起動後も新しい読戻しを要求する。
既存 snapshot の幾何形式は変えず、旧記録の追加証拠フィールドは空として読む。
コマンド権限、8,880セル上限、非原子的な観測という制約は
[共通読戻しの契約](server-readback.md) を参照。

## 独立した階段試験

`tools/make_stair_fixtures.py` が次の10ケースを定義する。
いずれも隔離 Java 1.21.11、`minecraft:vanilla` のみ、通常のレバー入力を使う。

- 内角4ケース: 上下・左右・4回転、形状変化と壁レバーの支持喪失。
- 外角2ケース: 上下・左右、隣接階段の移動による直線化。
- 到着先2ケース: 通常完了と短い反転での階段形状再計算。
- 段差配線2ケース: 高い側の `up` と低い側の `side`、信号伝搬。

10ケースとも、実際の入力適用時刻に基づく宣言区間について、tick末の全セル状態、
順序付き書込み、予約tickと破棄された配達試行、観測可能なcallbackが一致した。
checkpointと探索状態からの継続も再現する。全形状・全回路の等価性は主張しない。
原クライアント観測と独立確認を両方保存し、撤去・force-load解除・正常終了も確認する。

初期の読戻しは領域確認前後の時刻で判定していたため、全状態が一致しても確認を拒否する試験があった。
各条件自身の時刻を取得する実装へ改め、同一tick条件を維持した。
公開試験の4,785セルは複数コマンドのままでは条件を満たせなかったため、空気領域を
矩形比較にまとめ、領域全体を1つの条件確認コマンドで調べる実装にした。
失敗した試験を成功へ書き換えず、新しいrunとして再試験する。

## 公開MCPでの採用・配置・再起動・撤去

`tools/make_stair_assembly_fixture.py` は既存の混在試験を元に、階段を持つ子・親・Assemblyの
新しいRevisionを明示的に提案する。旧Revisionを上書きせず、入力とピストン本体の
状態関係をv16で再検証してから採用する。

`stairs-public-20260928-d` はX=144000、Y=180、Z=1000、90度回転、4,785セルで成功した。
公開APIを23回呼び、採用後・配置後・撤去後にMCPプロセスを再起動した。
15手順の配置と15手順の撤去を完了し、各試行に31件、計62件の異なる要求の読戻し証拠を保存した。
プレビュー未実施、外部変更、クライアント側の未ロード状態では書込み・撤去が拒否された。

ON時のクォーツ階段 `(144001,182,1000)` は、クライアントの `inner_left` に対して
サーバー確認結果が `straight` となった。game tick 165287と165310の両方で確認できた。
この時の `changed` は保存した初期状態との差を示す。回路故障の判定ではなく、
ONのままの撤去は拒否され、OFFに戻して初期状態と一致した後に撤去できた。
領域が空になったことをサーバーに確認し、所有するforce-loadを解除し、サーバーを正常終了した。

[公開APIの圧縮記録](evidence/stairs-public-20260928.json.gz) はリクエスト・応答、
読戻し、採用対象fixture、最終の永続記録、原本と使用コードのハッシュを含む。
完全なサーバートレースの代替ではなく、公開操作と保存証拠の記録である。
原本の連続トレースはローカルartifactのハッシュで識別する。

## 最終検証と制約

- 最終Rust回帰は396件成功（Minecraft全体314件にcompile-fail doctest 27件を含む、
  library 18件、translate 55件、MCP bridge 9件）。階段を誤ったcube定義に結び付けるとコンパイルエラーになる。
- MCP全84件は共通読戻し導入後に成功。その後の任意証拠フィールドとサーバー観測間隔の変更は、
  bridgeの最終回帰と公開実機試験で確認した。
- Node 11件、Python 33件成功。Pythonは43件の保存済みdevice実機記録と既存ドア等を再生する。
- workspace全targetのClippy（警告をエラー扱い）、fmt、diffチェック成功。
  Cargoはoffline/locked・1 job、Rustテストは1 thread。workspace全テストの一括実行は行っていない。

10ケースと読戻し再試験2件の計12キャプチャは、780 tick末状態、214書込み、30配達済みtick、
721 callback境界で一致した。詳細な入力時刻、原本・使用コードのハッシュ、失敗試験、検証コマンドは
[最終証拠一覧](evidence/stairs-runtime-20260928.json) を参照。
公開試験後の最後の変更は、複数回の形状照会があっても元のクライアント状態と最終確定状態の差だけを
記録する集計修正。サーバー問い合わせは変えず、形状の再変更と元に戻る場合をNodeテストで確認した。

支持喪失後のアイテム、階段の形状callback内部、隠れたイベント履歴は実機比較の対象外。
追加の階段材質・水没階段・板ガラス・流体・エンティティ・直接のピストン破壊は追加していない。
読戻し成功は、その後の他プレイヤーの変更を防ぐ保証や無条件の撤去・修復許可ではない。
