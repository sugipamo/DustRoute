# 既存機体の改造とサトウキビ試作

目的は、人間が作った停止中のピストン機体へ、通常MCPの観測・差分案・
プレビュー・適用・読戻し・条件付き取消を通して部品を追加できるようにすること。
今回の基準例は、6ブロックの機体へスライムとガラスを1個ずつ追加する収穫バー。
直接の管理コマンドによる試作結果は、通常MCPや収穫動作の合格証拠に昇格させない。
作業ブランチは `codex/existing-machine-edit`。

## 作業順序と完了条件

| 順序 | 作業 | 完了条件 |
| --- | --- | --- |
| 1 | 追加先を含む作業領域を観測 | 視線で対象を確かめ、指定した領域の空気・機体・周辺を完全取得し、不変の観測IDで後続処理へ接続 |
| 2 | 共通runtimeによる差分施工 | 新規施工と同じ設置・撤去・通知を使い、元の機体を残した追加手順と取消手順を検証。未知状態・観測外・非停止状態・完成図不一致を拒否 |
| 3 | 公開MCPと操作履歴へ接続 | `new_placement(revision_id)` → `show_operation` → `invoke_operation` → 条件付き `undo_operation`。全領域の前後を段階ごとに読戻し、書込み前に意図を保存。失敗・中断を再実行可能にしない |
| 4 | 観測した機体の有限飛行を検証 | テンプレートの合格を流用せず、起動条件・停止条件・運搬部品・到着図を明示して共通物理実行で検証 |
| 5 | サトウキビのブロック処理 | 破壊、支持を失った上部の除去、根元の成立条件を共通機構で扱い、既存作物の挙動を維持 |
| 6 | 診断の範囲を明確化 | 静的接続に関する所見と、機体・収穫の動作検証結果を区別。未対応を故障や合格へ読み替えない |

エンティティ、アイテム回収、自然成長、流体シミュレーション、サバイバル自動建築は保留。
別の作業を先に行うほうがユーザーの意図に適うと判断した場合は、その作業に着手せず
作業全体を停止し、根拠と具体案を報告する。宣言済みの差分施工は承認済み。

## 境界

- 作業領域は新しい観測として取得する。既存Revisionの範囲を未観測の空気で拡張しない。
- 初期モデルのキューは空と仮定する。静止した複数サンプルも隠れた予約や過去の履歴を証明しない。
- 差分施工は、完全なnative状態と共通物理モデルによる段階的施工の検査。
  飛行や収穫の型への適合、Blueprintの採用、所有権を自動的に確定しない。
- 保存された操作履歴から実行能力を復元しない。再起動後は履歴を読み、改めて観測・計画する。
- 条件付き取消は、施工後の全領域が一致する場合だけ可能。失敗後の自動取消・再試行はしない。
- 既存の採用・子の参照・配置済みAssemblyの期待値を、部分改造に合わせて自動変更しない。
- 公開MCP内部のコマンド施工と、通常の設置パケットによるサバイバル建築は別の入力経路。

## 現在の進捗

- 空気を明示する観測と省略する観測の集計差を修正済み。関連テスト4件合格。
- 差分施工のモデルを実装。今回の機体へのバー追加・取消、観測範囲外と不完全状態の拒否、
  観測面の変更による起動を完成図一致として受理しないことをテスト3件で確認。
- 作業領域の公開観測、MCP差分施工、共有の段階実行と保存記録を接続済み。
  ロードマップ1〜3のコードを実装し、MCP経由の追加・取消、周辺差分の拒否、
  読戻し失敗での停止、再起動後の履歴、読取り専用ポリシーを模擬transportで確認。
- 有限飛行の明示要件、サトウキビの物理機構、診断との接続（4〜6）は未完了。
- 公開MCPによる実機配置と収穫動作は未検証。今回、実世界は変更しておらず、
  稼働中のMCPバイナリへもまだ反映していない。

## 公開ツールの経路

```text
get_world({region: {min, max}, include_block_list: true})
  → test_circuit_change({circuit_id, changes: [...]})
  → new_placement({revision_id})
  → show_operation({operation_id})
  → 人間が具体的な案を確認
  → invoke_operation({operation_id, confirm: true})
  → get_operation({operation_id})
  → 必要な場合だけ undo_operation({operation_id, confirm: true})
```

領域は追加先の空気と停止中の機体を含め、プレイヤーの視線対象も含む。
計画は累積Revision差分と1ブロックの外周を再取得し、元の観測と照合する。
変更位置は1〜64、非空気ブロックは4096以下で、さらに配置数・領域のポリシー上限が適用される。
計画・プレビュー・実行前は、20 tickのbridge待機を挟んだ2回の完全・静止した観測を照合する。
この観測は予約イベントが存在しない証明ではない。

適用・取消の書込み前に操作記録を保存し、各コマンドの前後で全領域を読戻す。
失敗した試行は `needs_inspection` になり、同じ操作の再適用や自動取消を行わない。
履歴は `dustroute.world-edit.v1` として保存され、再起動後も `get_operation` で読める。
計画は実行前5分で失効し、再起動後には復元しない。

## 検証（2026-09-30）

- `cargo test --offline --locked -j1 -p dustroute-mcp --lib -- --test-threads=1`：116件合格。
  新規差分施工5件と、共有実行へ移した新規Assembly施工・撤去・再施工の回帰を含む。
- その後、取消時の外周差分の拒否と履歴の実行プロファイル照合を追加。
  `--lib electrical_edit` の5件を再実行して合格。
- `cargo test --offline --locked -j1 -p dustroute-translate --test electrical_modification -- --test-threads=1`：3件合格。
- `cargo clippy --offline --locked -j1 -p dustroute-mcp --features voxrig --lib -- -D warnings`：合格。
- 関連packageのfmt、差分の空白検査：合格。

MCPの試験transportはモデルの期待図を返す。
これらはAPI・保存・停止条件の回帰であり、Minecraftの挙動との比較証拠ではない。

## サトウキビ対応の前に必要な判断

対象版のローカルclassを `javap -p -c net.minecraft.block.SugarCaneBlock` で確認した。
Minecraft 1.21.11、Yarn `1.21.11+build.6` のnamed jarで、classのSHA-256は
`eb6b4a6e808b9cc8eca588e8f6ad5f1848aee5244a5148e95440dc7e71da2725`。
登録時のピストン反応は `DESTROY`。実装から確認できた支持条件は以下。

- 下が同じサトウキビなら成立する。
- 根元では下が `minecraft:dirt` または `minecraft:sand` のブロックタグに属し、
  その下ブロックの水平隣接に水のfluid tagまたは `frosted_ice` が必要。
- 形状更新時に不成立なら、1 game tick後のblock tickを予約する。
  予約時に即座には削除せず、実行時に再判定して不成立なら破壊する。
- `age=0..15` は自然成長の状態。自然成長を今回のモデルから外しても、
  実機の生育による状態変化を、構成の故障や合格へ自動変換しない扱いが必要。

現行 `physical::passive` は固定形状・乾いた階段・乾いたハーフブロックの宣言であり、
植物の支持条件を表せない。`piston_runtime::support` は隣接1面の支持と即時除去を扱う。
`ElectricalWorld` は領域内全ブロックの実行証拠を検査し、`water` は未対応として拒否する。
水をただの固体へ変換したり、観測領域から省略したりして根元検証を通すと、
完全観測・共通物理実行という今回の条件を満たせない。

このため、作物の専用分岐を足す前に、**観測済みの固定環境と、遅延した支持再判定を
共通の型として扱う基盤**を先に整えるのが適切と判断する。これは現在の電気部品・
固定形状テーブルより広い設計変更になるため、ユーザー指定の停止条件で作業を区切る。
基盤実装へは着手しておらず、ゴール全体も未完了。

次に検討する具体案は、(1) 土・隣接水をブロック状態から読める固定環境の宣言、
(2) 支持条件と1 tick後の再判定を既存キューへ接続する型、
(3) 初回は宣言した土と静的な水の範囲に制限し、流れ・水没・自然成長は未対応として
境界を明記、(4) その基盤でサトウキビの破壊・上部除去・根元残存を検証する順序。
流体シミュレーション全体やエンティティ対応を先に実装する提案ではない。
